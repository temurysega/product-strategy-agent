# Разбор опыта с привязкой к материалу

Каждое наблюдение: источник → экран/кадр/строка/временная метка → видимый элемент →
возможное препятствие → альтернативное объяснение → способ проверки.
Не выводи эмоцию, намерение, частоту ошибок или реальное поведение только из макета.

Если доступна лишь текстовая инструкция, анализируй последовательность и терминологию.
Цвета, контраст, размеры и расположение без изображения не оценивай. Если изображение
передано мультимодальной модели, сохраняй модель, файл и локатор; не объявляй OCR без проверки.
Аудио/видео без декодера или расшифровки — зарегистрированный материал, не выполненный анализ.

Путь: триггер → ожидание → действие → обратная связь → ошибка/отказ → восстановление.
Отдельно проверяй реальную возможность отмены, понимание доступа и доступность с клавиатуры,
если эти свойства есть в исходном материале. Рекомендация должна показывать компромисс:
меньше шагов не всегда лучше осознанного согласия.

Прототип — гипотеза. Проверка с пользователем фиксирует выполнение задачи, ошибки,
помощь, время и понимание; отсутствие жалоб не равно успешности.
