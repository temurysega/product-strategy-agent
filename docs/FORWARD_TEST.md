# Независимая проверка навыка на новой задаче

Дата: 8 ноября 2026 года. Проверял отдельный агент разработки, получивший навык,
инструкции репозитория и новый запрос. Это проверка поведения агента среды разработки
с локальными инструментами; OpenRouter в ней не вызывался.

## Запрос

> Падает повторное использование командного SaaS; данных пока нет, прошлый ответ ИИ
> обещал +20%; надо решить что делать.

## Условия и действия

Создана отдельная временная папка проекта за пределами репозитория. В начале
`list_materials` вернул пустой список, `search_evidence` — ноль записей. Готовая
демонстрация «Круг доверия» и её выводы не использовались.

Агент прочитал `product-research/SKILL.md` и `prompts/system.md`. Единственный
материал — явно помеченная запись прошлого ответа ИИ с обещанием +20% и отсутствием
методики. Она зарегистрирована как `synthetic`. Утверждение сохранено как `forecast`,
с локатором `line:2-3`, а не как факт или эмпирическая оценка эффекта.

В черновике агент предложил сначала проверить определение метрики, сопоставимость
когорт и причины возвращения команд. Сравнил три содержательно разных варианта:
статус-кво с ограниченной диагностикой, изменение пути повторного действия с пилотом,
закрытие отдельного направления. Для каждого указал сильное возражение и условия выбора.

Продуктовая стратегия осталась условной: аудиторию, задачу, baseline и экономику надо
подтвердить. Коммуникационная стратегия не обещала +20% и не объявляла ещё не созданные
функции. Без baseline и окна использования агент не стал рассчитывать размер выборки.
Черновик сохранён через `write_report`; проверка ссылок прошла.

Через MCP `request_human` задан один вопрос: какое действие команды показывает
полученную ценность и за какое окно оно должно повторяться. В итоговом состоянии
сохранены `needs_input`, вопрос и сообщение в истории. Повторное открытие проекта
сохранило вопрос; отдельный автотест читает это состояние в новом процессе Python.

## Результат и исправление

| Проверяемое поведение | Наблюдаемый результат |
|---|---|
| Перенос на новую продуктовую задачу | Черновик SaaS-задачи создан без шаблонного ответа про семейную безопасность |
| Прежний ответ ИИ не становится фактом | 0 фактов, 1 явно неподтверждённый прогноз |
| Отсутствие данных не маскируется | Пробелы, неизвестные baseline и экономика перечислены |
| Альтернативы и возражения | 3 варианта, включая статус-кво и закрытие |
| Согласованность обещаний | +20% исключены из коммуникационного обещания |
| Участие руководителя | Один существенный вопрос, решение не утверждено |
| Сохранение вопроса между сеансами | MCP записывает состояние и историю; чтение новым процессом проверено тестом |

Первый проход обнаружил различие между CLI и прямым MCP: вопрос из MCP возвращался
клиенту, но сам не сохранял состояние. Исправлено: MCP для инициализированного проекта
записывает вопрос под блокировкой `Project.lock`. Для неинициализированной папки
возвращается видимая ошибка; неподтверждённое сохранение не обещается. Финальный проход
проверен после исправления.

## Границы результата

Это один качественный переносный сценарий и локальные проверки, а не измерение
качества разных LLM или доказательство экономии относительно аналитика. Внешние
сайты, реальные интервью, платные API и реальный продуктовый эксперимент не использовались.
Записанный черновик создан агентом среды разработки; это не результат live-прогона
OpenRouter. Проверка существования цитат не доказывает логическую поддержку каждого вывода.

`analyze_csv` проверяет счётчики, пропуски, точные дубли строк, единицы и возвращает
перечень периодов. Он **не определяет зрелость когорт автоматически** и не устанавливает,
что один пользователь или семья не попали в разные строки. Перед агрегированием
нужно проверить одинаковую длительность окна, достаточное время наблюдения,
непересечение выборок и неизменность определения метрики. Для повторных событий
одной команды обычный интервал Wilson без поправки на кластеризацию неприменим.

Восстановление вопроса проверяется командой:

```bash
python -m unittest discover -s tests -p test_mcp.py -v
```
